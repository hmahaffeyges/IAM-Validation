# Task: build the website for the book "IAM's Law and Order"

**Who runs this:** a Claude Code cloud session on this repository, started by the author.
**How to deliver:** work on a new branch `website`, commit there, and open ONE pull request against `main`.
Do not push to `main`. Do not edit anything under `docs/book/` except adding build files (LaTeXML bindings) if needed.
The book's text, numbers and figures are final and owned by the author; the website only presents them.

## 1. What to build

A website on GitHub Pages (`https://hmahaffeyges.github.io/IAM-Validation/`), generated from the book's own LaTeX
(`docs/book/main.tex`), so that the website, the PDF and the Overleaf zip can never disagree.

- **Converter:** LaTeXML (`latexml` + `latexmlpost`), producing one HTML page per chapter, with MathML/MathJax equations,
  working cross-references (`\ref`, `\eqref`, `\cite`), figures from `docs/book/figures/` (PNG for the web), the bibliography
  from `docs/book/iam.bib`, and a clickable table of contents.
- **Custom macros** (in `docs/book/preamble.tex`) must render, not vanish. The status labels are coloured boxes in the PDF;
  on the web they become small coloured "chips" with the same words:
  `\derived` DERIVED, `\calc` CALCULATED, `\calibrated` CALIBRATED, `\measured` MEASURED, `\observed` OBSERVED,
  `\fitted` FITTED, `\conjecture` CONJECTURE, `\prediction` PREDICTION, `\openprob` OPEN PROBLEM, `\interp` INTERPRETATION.
  The register labels `\Spassed`, `\Sprecision`, `\Spending`, `\Stension` likewise (green, blue, amber, red).
  Provide LaTeXML bindings (a `.ltxml` file) for these and for any other preamble macro that LaTeXML does not know.
- **GitHub Action** (`.github/workflows/website.yml`): on every push to `main` that touches `docs/book/`, build the site and the
  PDF, and publish to GitHub Pages. Keep the existing `canon.yml` workflow unchanged.

## 2. Structure

- **Front page:** title, subtitle ("The Actualization of Reality — The Cost of Recording It, and the Price to Maintain It"),
  author (Heath W. Mahaffey), the line "IAM, the Informational Actualization Model", the seven Parts as large tiles,
  a "Download the PDF" button, and a "Cite this book" box (DOI placeholder `DOI-TO-BE-MINTED`, filled at release).
- **One landing page per Part** with its own short URL (e.g. `/part-2/`): the Part's title, a three-to-five sentence summary
  of what the Part claims and what a referee in that field should check (drafted from that Part's opening chapter, plain words,
  no new claims), the chapter list, a per-Part PDF download, and a "Run all checks in this Part" button (section 4).
  No Part requires reading another first; cross-Part links stay.
- **Per-Part PDFs:** build each Part as its own PDF in the Action (front matter + that Part + bibliography).

## 3. Look: one theme per Part (author-approved order: CMB sky, black hole, quantum/chip lattice, genome sky)

Body text is always high contrast and readable for 800 pages of equations. Provide a light/dark toggle the reader controls;
default light for chapter pages, dark for the front page and Part banners. Each Part gets an accent colour, a banner image and
opening art; nothing busy sits behind text or equations.

## 4. "Run this check" buttons (derivations in the browser)

`verify_book.py` at the repository root (it may arrive on `main` later; build against this interface) registers one check per
equation or number with `@check(label=..., chapter=..., part=..., heavy=...)`, offers `run(label=None, part=None)` returning
results, `python3 verify_book.py --json`, and lists the small data files it reads in `DATA_FILES` (read via `load_data`).

- Load Pyodide in the page, with numpy, scipy and sympy; fetch `verify_book.py` and the `DATA_FILES` from the same site.
- Next to each equation or number that has a check (match by its LaTeX `\label` or the script's label), show a small
  "Run this check" button. Output: PASS/FAIL, the book's value, the recomputed value, the tolerance.
- "Run all checks in this Part" on each Part page; "Run every check" on the front page.
- Checks with `heavy=True` (Planck chains, CAMB, the methylation chain) do not run in the browser: show the committed result,
  the one-line rerun command, and an "Open in Codespaces" link. Add a `.devcontainer/` that installs the Python dependencies.
- First load is slow (Pyodide download): say so once, with a progress indicator.

## 5. Comments

- **Hypothesis** (https://web.hypothes.is) embedded on every page for public, dated, named comments.
- A "Discuss this section" link on each chapter that opens a GitHub Discussion in a category per Part. If the categories cannot
  be created by the Action, list the steps for the owner in the PR description.

## 6. Rules (hard)

- Introduce no product, project, vendor or place names that do not already appear in the book's text; the site's own words stay generic.
- No "population" or "cohort" language in anything you write.
- Do not change any number, equation, figure, caption or sentence of the book. If LaTeXML cannot render something, render it as
  an image of the PDF fragment and list it in the PR description.
- No analytics or trackers. Third-party scripts only: MathJax, Pyodide, Hypothesis.
- Accessibility: alt text from figure captions, keyboard-navigable TOC, readable at 200 % zoom.

## 7. Done means

- The Action builds green on the branch and publishes a preview (or the PR shows how to preview locally).
- Every chapter page renders with its equations, figures, references and status chips; the PR lists every fragment shown as an
  image and every macro that needed a binding.
- Per-Part pages and PDFs exist; the themes match the table; the light/dark toggle works.
- At least one "Run this check" button works in the browser against `verify_book.py`.
- One pull request with screenshots: the front page, one page from each theme, one check running.
