Running patients, step by step

From the lab's IDAT files to a finished report — how to keep every patient separate, how to fill the intake, what one command runs the whole batch, and how a second blood draw automatically builds a trajectory against the first.

One-time setup (do once per computer)

Install a clean Python environment and unzip the engine folder. After this you never touch it again.

# 1. create the environment (once)
conda create -n cpg python=3.11
conda activate cpg
pip install methylprep numpy pandas scipy scikit-learn matplotlib

# 2. unzip CPG_CMB_v1 somewhere stable — that folder IS the engine

The very first patient run takes about a minute longer while the atlas unpacks itself one time. Every run after that is immediate.

The folder model — how patients stay separate

One folder per patient. Inside it, one dated subfolder per blood draw. The engine writes the report into the draw folder and keeps a running record of every draw in a baselines folder, so the next visit can compare.

patients/ ANON_0001/ ← one folder per patient (use an anonymized ID) baselines/ ← created for you; holds each draw's vector 2026-06-22/ ← one folder per draw, named by the draw date GSM...._Grn.idat.gz GSM...._Red.idat.gz questionnaire.json CPG_report_ANON_0001_....html ← written here after the run 2027-01-10/ ← the next draw, same patient ...new IDAT pair + questionnaire.json... ANON_0002/ 2026-06-22/ ...

Why it's safe: the intake file is always named questionnaire.json, so two patients can never share a folder — each one needs its own. That is what guarantees they never mix.

Running a batch — say she has 10 patients today

1

Make a folder for each patient, with today's draw inside

Create patients/ANON_0001 … patients/ANON_0010, and inside each one a folder named for the draw date, e.g. 2026-06-22.

2

Drop each patient's IDAT pair into their draw folder

From the lab you get a _Grn.idat and _Red.idat for each sample (gzipped is fine). Put each patient's pair into their dated folder.

The one thing to watch: the lab names IDATs by the chip barcode (like 207...R01C01), not by patient. Use the lab's sample sheet to match each barcode to the right patient as you sort the files in. That is the only place a mix-up could happen, so do it carefully.
3

Fill the intake form for each patient and save it into their draw folder

Open cpg_intake_form.html in Chrome or Edge. Fill the four required fields — anonymized ID, date of birth, sex, and sample type — plus anything else useful. Click Save questionnaire.json and, in the dialog, navigate into that patient's dated folder and save. Repeat for all ten.

In other browsers the file lands in Downloads instead; just move it into the patient's draw folder. The file must be named questionnaire.json and sit beside that patient's IDATs.
4

Run the whole batch with one command

From inside the engine folder:

conda activate cpg
cd CPG_CMB_v1
python run_batch.py --patients /path/to/patients

It walks every patient, runs each draw that doesn't already have a report (in date order), and prints a summary when it finishes. Re-running it is safe — already-finished draws are skipped.

5

Open each report

Every report is the CPG_report_*.html file inside that patient's draw folder. Double-click to open it in any browser. It opens with the verdict, then the cell-by-cell readout, the confirmation layer if anything was flagged, and — from the second draw onward — the trajectory.

A returning patient — the next blood draw

Nothing new to learn. Under that patient's existing folder, add a new dated draw folder, drop in the new IDAT pair and a fresh questionnaire.json, and run the batch again.

# six months later, same patient
patients/ANON_0001/2027-01-10/   ← new IDAT pair + questionnaire.json
python run_batch.py --patients /path/to/patients
Automatic: because the patient ID matches, the engine finds the earlier draw, compares the two, and adds a Trajectory section to the new report — showing which cell classes rose or fell, whether any crossed the 1.07 Warburg or 1.10 breach line, and whether the whole architecture moved toward or away from healthy. Over five years and ten draws, every one is on record and each new report reads against the last.

What the engine handles for you

  • Separation — one folder per patient; their inputs, report, and history live together and never mix.
  • Calibration — each IDAT is normalized on its own (dye-bias + probe-type), no cohort, no batch.
  • Two deconvolvers — a conservative fit for the reliable composition and a sensitive one that surfaces faint shed signal; the report explains both.
  • Confirmation — if a disease pattern is flagged, a second chain (Mahalanobis + literature anchor + residual map) runs automatically and adjudicates whether it is real or a bulk-composition artifact.
  • Trajectory — every draw's vector is saved; the next draw compares against it with no extra steps.
