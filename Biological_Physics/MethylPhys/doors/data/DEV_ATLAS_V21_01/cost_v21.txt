Atlas v2.1 cost and time sheet (readiness L11), written 2026-10-14 before launch.
Source of timing: v2's measured block 0 (atlas/v2/records/14_stageB_timing_block.log): 1,163 loci, 74 cells, 964 s, 0.829 s per locus.
Scaling: the plan's cost model (atlas_v21_plan.md section 4), s/locus = 0.829 x (obs per locus + 2 x cells + 1) / (301 + 2 x 74 + 1) x f_tree, f_tree 1.0 to 1.15.
Observations per locus MEASURED by the dry run (dryrun_v21.txt, blocks 0, 350, 699): 598.5, 573.7, 593.3; the largest, 598.5, is used.
s per locus: 1.395 (central) to 1.605 (upper). Loci about 814,000 in 700 blocks (v2's).

m7a.32xlarge, 128 cores, 512 GB (fits the 128-core quota today): 16 processes -> 19.7 to 22.7 h
   cost at about $7.40/h on demand: $146 to $168
m7a.48xlarge, 192 cores, 768 GB (needs a quota increase): 24 processes -> 13.1 to 15.1 h
   cost: about 1.5 x the hourly price of the 128-core machine for about 2/3 the hours, so about the same total

Memory: v2 blocks peaked at about 13 GB; v2.1 blocks scale with the cost (about 1.7 to 2.3 x), about 23-30 GB each, so 16 at once need about
370-480 GB: inside 512 GB, not inside the 246 GB machine v2 used. B1 measures one block's peak before the number of processes is fixed.
Price caveat: $7.40/h is the m7a.32xlarge list price recalled in the project record (the AWS price list is not readable from this account);
the author's billing page is the check. Spot is cheaper but can be reclaimed; the run skips finished blocks, so a reclaim costs time, not results.
